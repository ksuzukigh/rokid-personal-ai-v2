# 私のAI V2

**眼鏡から、いつものAIとの会話と仕事を続ける。**

「私のAI」は、Rokid AI Glasses RV101を、Macで普段使っているCodexの会話への音声の入口にする、鈴木啓一の個人開発プロジェクトです。

「さっきの記事の相談を続けたい」「新しく、このテーマを調べたい」と自然に話しかけます。適切なMacの会話でAIが依頼を進め、聞き返し、途中経過、結果が眼鏡へ戻ります。机に戻ったら、同じ会話で作業を続けられます。

この公開リポジトリでは、開発したコンセプト、設計の理由、自分の環境で似た仕組みを作るための情報を紹介します。実働版のソース一式、APK、AIX、インストーラーは配布していません。

![私のAI V2の構成。眼鏡から音声をMacへ送り、受付AIが会話先を提案し、Macの会話が調査や作業を担当。途中経過と結果は眼鏡へ戻る。](docs/images/system-overview.svg)

## こんなときに使う

- Macで進めていた記事の相談を、歩きながら続ける。
- 新しい相談を眼鏡から始め、帰宅後も同じ会話で続ける。
- Webや自分の資料を調べ、必要なら確認してから文書やスライドを作ってもらう。
- AIからの質問に声で答え、途中経過と結果を眼鏡で読む。

上記は使い方を説明するための例です。実際に確認した操作と条件は[検証範囲](#実機で確認した範囲と制約)にまとめています。眼鏡を閉じた後の通知や、あらゆるスキル・変更操作の動作を保証するものではありません。

## なぜ作ったか

AIとの相談では、直前の話だけでなく、途中まで進めた仕事、自分の資料、普段の道具が大切です。眼鏡のために毎回別の会話を始めると、その文脈を引き継ぐ手間が生じます。

V2では、Macの普段の会話を実際の作業場所として使います。眼鏡には音声の入口と表示を任せ、受付AIには会話先の判断を、選ばれたMac会話には調査や文書作業を任せます。[コンセプトと設計の理由](#コンセプトと設計の理由)

## V1から何が変わったか

[V1](https://github.com/ksuzukigh/rokid-personal-ai)にも会話、調査、確認後の保存・編集機能がありました。V2の中心は、**Macの通常の会話につなぎ、その履歴、作業場所、道具、スキルを使って続けること**です。

| 観点 | V1の参考公開 | V2 |
| --- | --- | --- |
| 会話 | 眼鏡向けの会話処理を中心に構成 | Macの通常の会話を続け、新しい会話も始める |
| 作業 | 専用の経路で調査や限られた保存・編集 | 選ばれたMac会話が利用可能な道具・スキルで担当 |
| 役割 | 眼鏡向けの受付に機能をまとめる | 会話先を判断する受付と、実作業をする会話を分ける |
| 公開内容 | 説明と参考コード | コンセプト、設計資料、再現手引き、データ例 |

V1は開発の前段階を理解する資料として残しています。[V1とV2の詳しい関係](#v1とv2の関係)

## 自分の環境で作るには

RV101のYodaOS・AIUI、Macの常設サービス、音声の文字起こし、Codexとの連携、認証付きの通信経路を組み合わせます。ObsidianやGoogle Driveは必要に応じて接続します。

開発経験がある方、またはAIと相談しながら実装と検証を進められる方を想定しています。公開資料をダウンロードするだけでは動きません。特に、既存のデスクトップ会話への接続は利用環境に合わせた調査が必要です。まずMac内で専用のテスト会話を作り、文字だけの往復から進める方法を[再現の手引き](#自分の環境で作るための手引き)で説明しています。

実働版の基準は2026年9月26日に実機確認を終えた個人環境です。公開資料の初版は2026年10月10日です。他の人の環境での通し再現は確認していません。

## コンセプトと設計の理由

「私のAI V2」は、Macの普段のAIとの会話を、Rokid AI Glasses RV101から自然に使い続けるための仕組みです。眼鏡用の別の仕事場を作るのではなく、普段の会話を仕事場として使います。

### 会話を持ち出す

たとえば、Macで記事の構成を相談していたとします。外出中に別の案を思いついたら、「さっきの記事に、この視点も入れたい」と話す。適切な会話が選ばれれば、その履歴や作業場所を踏まえて相談を続けられます。

帰宅したら、同じMac会話を開きます。音声で話した内容とAIの返事をたどり、資料を見ながら次の作業へ進めます。AIの回答だけでなく、続いている仕事の文脈を使えることを重視しています。

### 入口と実作業を分ける

眼鏡は録音と表示を担当します。Mac側の受付AIは、発言と会話の文脈から、現在の会話を続けるか、別の会話へ移るか、新しい相談を始めるかを提案します。

受付AIはファイルやサービスを操作しません。実作業は、選ばれたMac会話が担当します。こうすると、調査や文書作成のために、同じ機能を眼鏡側へ重複して作り込む必要が減ります。

受付にはLUNAを使っていますが、特定のモデル名がこの設計の本質ではありません。会話先を判断する役割と、依頼を実行する役割を分けることが大切です。

### 利用者に操作の分類をさせない

利用者は「質問」「検索」「保存」などの分類を選ばず、やりたいことを自然に話します。受付AIや作業AIが意味を理解し、情報が足りなければ聞き返します。

機械側で固定するのは、日本語を理解する規則ではなく、実際の会話先、権限、確認内容、送信回数などの境界です。AIが会話名を説明しただけでは送信せず、Macが実際に解決した会話名を画面へ出します。

### 確認は実際の影響に合わせる

現在の会話の普通の続きには、毎回儀式のような確認を挟みません。別の会話へ移るとき、新しい会話を作るときには、提案された送信先を確認します。

保存や編集などの直前には、作業を担当するMac会話が、対象と内容を示して確認を受けます。会話先の確認、録音開始、文書変更の確認は、それぞれ別の意味を持ちます。

### 小さな画面に必要な情報を残す

眼鏡には会話名、実際の回答モデル、録音中の状態、途中経過、返事を表示します。モデル名だけ取得できない場合も、回答本文まで隠さないようにします。同じ途中報告の再描画を抑え、読んでいる画面の点滅を減らします。

長い本文やリンクの確認には、本人用WebやMacを併用できます。眼鏡だけであらゆる確認を済ませることを目標にはしていません。

### 再現する人に伝えたいこと

特定の眼鏡やAIに合わせた実装をそのまま移植するより、会話の継続、役割の分離、正確な確認、二重実行を避ける仕組みを、自分の道具に合わせて組み直すと応用できます。他の機種での実動作は別途検証が必要です。

## 会話と操作の例

以下はV2の利用体験を説明するために作成した架空の会話例です。実際の会話の転載、発言どおりの応答保証、全操作の実機検証記録ではありません。

### Macで進めていた相談を続ける

眼鏡で「私のAI」を開き、「タップして話す」を1回操作すると録音が始まります。前の会話が表示されている場合は「タップして続けて話す」です。話し終えたら、もう1回操作して録音を終えます。

> 私：さっきの記事の相談を続けたい。外で使う場面も入れたい。
>
> AI：記事の相談の続きを、この会話で進めますか？
>
> 続ける会話：スマートグラス記事の構成
>
> 私：はい、その会話です。
>
> AI：外出中に使った場面を、どの章へ入れるか考えましょう。どんな場面でしたか？

確認画面の会話名は、受付AIが自由に書いた呼び名ではなく、Macが選んだ実際の送信先です。確認できた元の発言が、その会話へ1回だけ届きます。

返事の後は「タップして続けて話す」の1回操作で次の録音を始めます。普通の続きの発言について、会話先を毎回確認し直すことはしません。

### 新しい相談を始める

> 私：新しい相談で、旅先で思いついたアイデアを整理したい。
>
> AI：新しい会話を始めますか？
>
> 新しく始める会話：旅先のアイデア整理
>
> 私：それでお願いします。

確認後にMacへ新しい会話を作り、最初の依頼を渡します。受付の言い換えだけを依頼本文にせず、確定した元の発言を使います。あとでMacから同じ会話を開いて続けられます。

### 調査と資料作成を頼む

> 私：このテーマを調べて、メモとスライドにまとめたい。
>
> AI：誰に説明する資料で、何を一番伝えたいですか？
>
> 私：同じ仕組みを試したい人に、全体の構成を伝えたい。

選ばれたMac会話が、利用できる道具やスキルで作業を進めます。聞き返しへの答えも同じ会話へ戻します。途中経過が変わったときだけ眼鏡の表示を更新し、最終回答へ自動で切り替えます。

保存や作成などの変更が必要な段階では、対象と内容を示して確認を受けます。スキルに公開禁止などのルールがある場合も、そのルールを維持します。

### 表示していた質問が古くなったとき

眼鏡で質問を読んだ後に、MacやWebから会話を進めることがあります。その状態で眼鏡から「はい」と答えても、新しい質問への同意として転用しません。

実際に表示した質問と現在のMac会話が一致しなければ、古い返答を送らず、最新の内容を表示して聞き直します。認識した言葉が確認の文脈に合わない場合も、同意と決めつけません。

### 終了と通信の回復

アプリを開いただけでは録音しません。録音は最長60秒で、原音と一時音声は処理後に削除します。終了操作では眼鏡側の録音と短命な接続を終えます。

通信が切れた場合は、同じ依頼の状態を確認して結果を取り戻します。返事が見えないという理由だけで、同じ依頼を送り直しません。眼鏡を閉じることと、Macで始まった仕事を取り消すことは別です。終了だけで作業の取消や実行済み変更の巻き戻しを保証しません。

## システム構成

V2の中心は、眼鏡とMacの通常の会話をつなぐことです。認証、文字起こし、会話先の判断、送信、結果の表示を分け、実作業はMac会話が担当します。

![私のAI V2の構成図](docs/images/system-overview.svg)

### 部品ごとの役割

| 部品 | 担当 | 担当しないこと |
| --- | --- | --- |
| RV101のAIUI Agent | 録音開始・終了、音声送信、状態・会話名・返事の表示 | ファイル編集や資料作成の実処理 |
| 通信経路 | 固定HTTPS名からMacの必要な受付へ届ける | AIの判断や、アプリ利用者の本人確認の代替 |
| Mac受付サービス | 登録端末の照合、短命な接続、依頼と表示状態の保持 | 眼鏡から指定された任意の会話IDを無条件に採用すること |
| WhisperとVAD | Mac内で発話区間を確認し、音声を文字へ変換 | 会話先の判断、背景話者の完全な分離 |
| 受付AI | 元の発言と文脈から会話先を提案、必要なら聞き返す | ファイル操作、スキル実行、権限付与 |
| 会話への接続部 | 実会話先を照合し、元の発言を送り、進捗と結果を読む | AIの言い換えから勝手に別の依頼を作ること |
| MacのCodex会話 | 履歴、作業場所、利用可能な道具・スキルで調査や作業 | 会話先の選択だけを担当する受付AIへの権限委譲 |
| 本人用Web | 長い本文や確認内容を補助的に読む | 利用前に必ず操作する作業選択メニュー |

### 依頼から結果まで

1. 利用者の操作で録音し、認証済みの接続から音声をMacへ届ける。
2. Macが文字化し、原音と一時音声を削除する。
3. 受付AIが現在・別・新規の会話を判断する。
4. 別会話・新規会話では、Macが実際に解決した会話名を表示して確認する。
5. 会話と依頼を固定し、元の発言を1回だけ送る。
6. Mac会話の途中経過と最終回答を、同じ依頼に結び付けて読む。
7. 変化した本文だけを眼鏡へ表示する。聞き返しへの返答も同じMac会話へ戻す。

### 端末登録とその回の接続

初回の本人確認付き登録と、その後の会話接続を分けています。生成したAgentに有効な秘密を埋め込まず、登録後の実行時に端末へ渡す設計です。

登録済み端末でも、会話に使う接続は短命にします。Macが期限と登録解除を管理します。端末保存のAPIがあることと、秘密を安全に保管できることは同義ではありません。[安全の設計](#認証-録音-実行確認の設計)

### 通信経路

個人環境では、専用の固定HTTPS名とCloudflare Tunnelを使っています。Macから外向きにトンネルを張り、ローカルの受付へ届けます。これはCloudflareの[公式の接続モデル](https://developers.cloudflare.com/cloudflare-one/networks/connectors/cloudflare-tunnel/)に基づく構成です。

トンネルだけで、利用者の認証や操作権限が決まるわけではありません。眼鏡の登録、短命な接続、本人用Webの認証、公開する経路の限定を別に設計します。常設Macの待受けと、会話ごとの接続を区別します。

### Codex接続の重要な違い

Codex App Serverには、会話を作成・再開し、入力を送り、イベントを読むための公式資料があります。[OpenAI公式資料](https://learn.chatgpt.com/docs/app-server)

個人環境のV2では、新規会話の初回と、既存デスクトップ会話の続きで接続方法を分けています。初回は会話を作成したApp Server接続で始め、既存会話にはデスクトップ側のキュー経路を使います。

確認した公式ページには、この既存会話用キューの同じ呼び出し仕様は掲載されていません。一般のApp Serverクライアントを作るだけで、開いているデスクトップ会話へ同じように投入できるとは案内していません。ここは利用中のアプリとバージョンで調査する接続部です。会話履歴ファイルへの直接追記で代用しないでください。

独立したテスト会話を使う最小構成と、デスクトップ会話を持ち出す完成像を、[再現の手引き](#自分の環境で作るための手引き)で分けています。

### 保存する状態

| 状態 | 用途 | 保存上の扱い |
| --- | --- | --- |
| 端末登録 | 接続を許可する端末の管理 | 秘密を公開物に入れず、解除できるようにする |
| 会話先の対応 | Macの会話と眼鏡の表示を結ぶ | 会話IDは内部で保持し、画面には実会話名を出す |
| 確認待ちの提案 | 元の依頼と実際の送信先を保持 | 誤認識や聞き直しで勝手に失わない |
| 依頼の送信意図と結果 | 再起動や通信断での再送を避ける | 依頼ID・本文・実会話先を対応させる |
| 表示した回答の識別情報 | 古い質問への返答を防ぐ | 回答ID、ターン、本文の識別を次の返答へ結ぶ |
| 原音と変換用音声 | 文字起こし | 処理後に削除し、通常の会話履歴とは分ける |

## V1とV2の関係

[V1の公開リポジトリ](https://github.com/ksuzukigh/rokid-personal-ai)は、眼鏡からMacのAIへ話しかける仕組みと、その構成を読むための参考コードを残しています。V2はその発展として、Macの普段の会話と仕事を眼鏡から続ける設計を紹介します。

### 残す理由

V1には、音声をMacへ送って文字化する、返事を眼鏡へ戻す、確認後に限られた保存・編集を実行する、という土台があります。V2が何を引き継ぎ、何を変えたかを理解する資料になります。

V1の記事やリンクから来た人も、当時の説明を読めるよう、既存リポジトリとURLを残します。V2は別リポジトリにし、両者から相互に案内します。

### V2で変えた中心部分

| 観点 | V1 | V2 |
| --- | --- | --- |
| 会話の続き先 | 眼鏡向けの専用会話処理 | Macの通常の会話 |
| 会話の選択 | 専用の会話の中で継続 | 現在の続き、別の会話、新しい会話を自然に判断 |
| 調査・文書作業 | 専用の処理と制限された操作 | Mac会話が持つ道具・スキルを使う |
| 受付の役割 | 眼鏡向けの処理をまとめる | 意味理解と会話先の提案。実作業は担当しない |
| 表示 | 音声往復と回答を中心に構成 | 実会話名、実モデル、途中経過、最終回答、Mac側の新質問を共有 |

V1にも調査と保存・編集機能があります。「V1は質問だけ、V2は作業もできる」という区分ではありません。

### コードを混ぜない

V1のコードはV1の参考実装です。V2の資料に書かれた会話接続や端末登録が、V1のコードへ実装済みであるとは限りません。

V2の公開資料には、個人用実装のソースやGit履歴を持ち込んでいません。説明用の仕様とデータ例から、自分の環境に合った部品を組み立てます。V1の制限や操作文言を、V2の現行仕様として流用しないようにしてください。

## 自分の環境で作るための手引き

この手引きは、V2の設計を参考に自分用の仕組みを組み立てる順序を示します。実働版を再配布するセットアップ手順ではありません。公開資料だけでは起動せず、各段階の実装と検証が必要です。

### 最初に決めること

まず、眼鏡から何をしたいか、どの資料を読みたいか、どの変更を許可するかを決めます。「既存のMac会話を眼鏡から続ける」のが完成像ですが、最初は専用のテスト会話で、文字の往復だけを作ると部品を確かめやすくなります。

| 構成 | 得られる体験 | 自分で用意するもの |
| --- | --- | --- |
| Mac内の最小構成 | 専用テスト会話への入力と返事 | Codexとの接続部、依頼の記録、結果の読取 |
| 眼鏡との往復 | 実音声を送って眼鏡で返事を読む | AIUI Agent、文字起こし、登録・通信・表示 |
| V2の完成像 | 普段のMac会話を選び、同じ仕事を続ける | デスクトップ会話の一覧・照合・送信・同期の接続部 |

最小構成が動いても、V2全体を再現したことにはなりません。

### 必要な環境

| 項目 | 役割と確認事項 |
| --- | --- |
| Rokid AI Glasses RV101 | YodaOSのAIUIで画面、録音、入力、通信を扱える検証端末 |
| Hi RokidとAIUI Studio | 自分用Agentの登録、配置、資源更新。利用できる権限・現在の手順を確認する |
| ADBを使う開発環境 | 使う場合はHi Rokid側で開発者モードを有効にする。開発用5ピンケーブルだけではADBは有効にならない |
| Mac | 受付、状態保存、文字起こし、AI接続を動かす。必要な間はログインし通信できる状態を保つ |
| Node.js等の実行環境 | Mac受付と接続部を実装するために用意する |
| Codexと利用者自身のアカウント | 会話、利用モデル、権限、利用枠、道具・スキルの接続を確認する |
| WhisperとSilero VAD | Mac内の文字起こし。導入例はwhisper.cpp。モデルの配置と利用条件も確認する |
| 自分で管理するHTTPS経路 | 外出先から使う場合に必要。個人環境ではCloudflare Tunnelを使用 |
| テスト用の資料・保存場所 | ObsidianやGoogle Driveを接続する場合に、本番資料と分けて用意する |

Androidの補助アプリを自作する場合は、JDK・Android SDKなども必要です。AIUIの操作や権限をAndroid一般の仕様で置き換えず、[Rokidの資料](#参照資料)とRV101で確かめます。RV203など他機種で同じ動作をするとは扱いません。

### 自分で実装する部品

以下は推奨する分割例です。個人用実装のファイル名やディレクトリを公開したものではありません。

```text
自分のプロジェクト/
  glasses-agent/       録音・表示・通信・終了
  mac-service/         認証、受付、状態保存、常設起動
  speech/              VAD、文字起こし、一時音声の削除
  conversation-guide/  会話先を提案する受付AI
  conversation-link/   実会話先の照合、送信、状態・結果の読取
  owner-web/           必要なら本人用の大きな表示
  checks/              模擬・Mac・実機それぞれの確認
```

役割、入出力、例外時の動きを[要求仕様](#要求仕様とデータ例)にまとめています。[AIに渡す開発依頼](#aiと一緒に作るための開発依頼)を併せて使えます。

### 作る順序と合格の目安

| 段階 | 実装すること | 次へ進む前に確かめること |
| --- | --- | --- |
| 1. Mac内の文字往復 | 自分の専用テスト会話へ一文を送り、完了状態と本文を読む | 入力・会話・結果が対応し、失敗を成功扱いしない |
| 2. 状態の保持 | 依頼ID、送信意図、会話先、結果を保存する | 通信応答が不明でも自動再送しない。再起動後に同じ依頼を読める |
| 3. 固定文字の眼鏡表示 | 自作Agentと認証付き経路で固定文を往復する | 未登録・失効端末を拒否し、実画面で本文を読める |
| 4. 実音声の往復 | 操作で録音し、文字化して返事を表示する | 開いただけで録音しない。無音、終了、失敗時も一時音声を削除する |
| 5. 会話先の提案 | 現在・別・新規の会話をAIが提案する | 実会話名を表示し、元の発言を保持。訂正や不明な同意に対応する |
| 6. 既存Mac会話への接続 | 自分のデスクトップ環境で続き先へ渡す | 対象・本文・送信回数・モデルが実会話と一致する |
| 7. 進捗と聞き返し | 同じ依頼の途中経過、質問、結果を同期する | 同じ本文で点滅しない。古い表示への返答を新質問へ送らない |
| 8. 資料の読取と変更 | 許可した資料・道具・スキルを使う | テスト資料で対象と内容を示し、確認後に実行。実結果を読み戻す |
| 9. 復旧と終了 | 通信断、Mac・眼鏡再起動、通常終了を扱う | 同じ依頼を二重実行せず、原音・一時音声・短命接続を残さない |

模擬確認、Macでの確認、眼鏡の実音声・実表示の確認を分けて記録します。Macだけで成功したものを眼鏡の合格として扱わず、合格済みの操作を毎回繰り返す必要もありません。

### Codexとの接続を作るとき

一般的な会話クライアントの出発点は、[Codex App Serverの公式資料](https://learn.chatgpt.com/docs/app-server)です。初期化、会話の作成・再開、入力、イベントの読取、完了状態を扱う接続部を、自分の環境で確認します。

個人用V2が利用する既存デスクトップ会話のキュー経路は、今回確認した公式ページの一般向け呼び出し仕様とは別です。利用しているアプリの機能・バージョンで調査し、適切な経路がなければ、まず独立したテスト会話に留めます。会話ファイルの直接編集、アカウント認証の抜き取り、無条件の権限拡張で接続を代用しません。

この資料はAPIキーの購入や従量課金の利用を前提にしていません。選ぶ接続方法によって認証や課金条件が異なるため、自分のアカウントで確認してください。モデル名を固定でコピーせず、実際に利用できるモデルを選びます。

### 外出先からの通信

最初にMac内の動作を確認し、その後で自分用HTTPS名と限定した受付経路を用意します。Wi-Fiやスマートフォンのテザリングは眼鏡をインターネットへつなぐ手段であり、Mac受付の認証の代わりにはなりません。

トンネルの管理用秘密と、眼鏡の登録情報と、会話ごとの短命な秘密を分けます。初回登録の本人確認、登録解除、期限切れ、未登録端末の拒否も確認します。秘密を生成済みAgentへ埋め込みません。

### 最初の再現目標

専用のテスト会話で「短い相談 → AIの聞き返し → 声で返答 → 最終回答」を1回通します。その後に既存のMac会話、資料の読み取り、確認後の変更へ広げます。途中で使えない接続・権限が見つかった場合は、止まった部品と条件を記録して設計を調整します。

## 要求仕様とデータ例

この仕様は、V2と似た仕組みを自分で実装するために整理した参考設計です。以下の名前・JSON・疑似コードは説明用で、個人用実働版の通信仕様や互換APIではありません。

### 体験の要求

1. 利用者は操作メニューで分類せず、自然に依頼する。
2. 起動だけでは録音しない。「タップして話す」または「タップして続けて話す」の1回操作で始め、話し終えたら1回操作で終了する。最長60秒。
3. 現在の会話の普通の続きは同じMac会話へ渡す。別会話・新規会話は、実際の送信先名を表示して確認する。
4. 質問と返答、途中経過、最終回答を同じ会話・依頼へ結ぶ。利用者の発言は「私：」、AIの発言は「AI：」と表示する。
5. 現実を変える直前には、対象・内容・影響を示して確認する。各道具やスキルの権限・ルールも守る。
6. 通信結果が不明な場合は同じ依頼の状態を読み、無条件に再実行しない。

### 部品の入出力

| 部品 | 入力 | 出力と責任 |
| --- | --- | --- |
| 音声受付 | 登録済み端末、その回の接続、録音 | 発話候補、認識状態、録音ID。変換後の一時音声削除 |
| 受付AI | 発話候補、現在の会話、候補一覧、確認待ちの提案 | 会話先の提案、説明または聞き返し。実操作はしない |
| 送信先解決部 | AIの提案とMacの実会話一覧 | 実会話ID・実会話名・作業場所を照合した内部対象 |
| 確認管理 | 元の依頼、照合済み対象、表示、返答 | 未確定・確認済み・取消・失効。対象が変われば再確認 |
| 会話接続部 | 確定した元の発言、内部対象、依頼ID | 送信状態、途中経過、質問、最終回答、失敗 |
| 表示共有 | 会話と依頼に対応する本文 | 表示回答IDと内容。変化した本文だけを更新 |

「現在・別・新規」などの出力値は接続先を扱うための区分です。日本語の意味理解を固定キーワードへ置き換えるものではありません。

### 発話候補

```json
{
  "recording_id": "example-recording-01",
  "transcript": "さっきの記事の相談を続けたい。外で使う場面も入れたい。",
  "transcript_state": "candidate",
  "displayed_answer_id": "example-answer-03"
}
```

文字起こし結果は候補です。確認待ちで文脈に合わない認識結果を、確定した同意や「私：」の発言にしません。`displayed_answer_id`は、何を読んだ後の返答かを照合するために使います。

### 受付AIの提案

```json
{
  "decision": "propose_existing",
  "candidate_ref": "example-candidate-02",
  "message": "記事の相談の続きを、この会話で進めますか？"
}
```

`candidate_ref`は、Macが渡した候補へ戻るための参照です。AIに実会話IDやファイルパスを作らせません。候補の名前や本文は参照データとして扱い、そこに含まれた指示を受付AIへの命令にしません。

Mac側で実在・権限・会話状態を照合してから、以下のように表示します。

```text
AI：記事の相談の続きを、この会話で進めますか？
続ける会話：スマートグラス記事の構成
```

表示する名前は実際に解決した対象から取得します。確認待ちの間は元の発言と対象を保持し、訂正・取消・聞き直しを扱います。新規会話は、提案の確認後に作成します。

### 送信記録

```json
{
  "request_id": "example-request-01",
  "conversation_ref": "example-resolved-conversation-02",
  "original_text": "さっきの記事の相談を続けたい。外で使う場面も入れたい。",
  "delivery_state": "intent_saved",
  "expected_answer_id": "example-answer-03"
}
```

これはMac内部の説明用記録です。端末が任意の送信先を指定できる設計ではありません。確認で得た「はい」を新規依頼本文にせず、保持した元の発言を渡します。通常の続きの発言は、その発言自体を渡します。

送信意図を永続化してから、会話先と最新の質問を再照合します。既存記録があれば、新しい送信を発行する前に、その依頼の状態を読みます。

```text
記録済みの同じ依頼がある → 同じ依頼の状態を読む
新しい依頼である          → 送信意図を保存する
送信先・質問が変わった    → 送信せず最新表示または再確認へ
初回送信を発行した        → 結果を待ち、依頼IDで照合する
応答が途切れた            → 状態不明として保持し、同じ依頼を読む
実失敗が確定した          → 途中の変更も確認し、再実行は別途判断する
```

送信直前の再照合だけで、競合のない完全な一回実行を証明できるわけではありません。受け側の重複抑止や、実変更の側でも確認を維持します。結果不明を自動再送で埋め合わせないことが重要です。

### 途中経過と結果

```json
{
  "request_id": "example-request-01",
  "conversation_ref": "example-resolved-conversation-02",
  "answer_id": "example-answer-04",
  "state": "completed",
  "text": "外出中の利用場面を入れるなら、体験を説明する章が合いそうです。",
  "model_label": "利用中の実モデル名"
}
```

受信した結果の依頼と会話を照合し、別の仕事の本文を表示しません。`completed`以外の状態を最終成功にしません。同じ本文の再受信で画面を描き直さず、変化した途中経過と最終回答を反映します。

モデル名は、Mac会話の実際の設定から取得します。受付AIのモデルを作業モデルとして表示しません。モデル情報だけの取得失敗なら本文を保ち「モデル確認中」と表示します。

モデル切替を実装する場合は、使用中モデルと明示した標準モデルを分けます。モデルについての評判や比較を切替依頼と誤解せず、利用可能な一覧で解決します。モデル変更で権限を広げません。

### 古い質問への返答

返答には、眼鏡へ表示した回答の識別情報を結びます。Mac側では対象会話の最新ターンと本文も再確認します。

| 条件 | 扱い |
| --- | --- |
| 表示した質問とMacの質問が一致 | 意味を確認し、同じ会話へ返答する |
| MacまたはWeb側で会話が先に進んだ | 古い返答を送らず、最新の内容を表示する |
| 質問の照合ができない | 同意として実行せず、状態を確認する |
| 認識した返事が確認の文脈に合わない | 元の依頼と提案を保持して聞き直す |

### 実変更の確認

文書作成・編集などは、作業を担当するMac会話が、対象・内容・保存先や送信先・影響を示します。確認はその提案だけへ結び、古い確認を再利用しません。

対象や本文が確認後に変わったら再確認します。実行後は文書・セル・サービスの実状態を読み戻します。「実行しました」というAIの返事だけを成功証拠にしません。

### 実装時の合格条件

[再現の手引き](#自分の環境で作るための手引き)の段階ごとに、正常な往復、取消、曖昧な認識、古い質問、失効、送信応答の欠落、部分失敗、終了を確かめます。認証処理と削除処理は疑似コードだけで済ませず、自分の実装で検証してください。

## AIと一緒に作るための開発依頼

以下を、開発を手伝うAIへ渡してください。このリポジトリの資料も読めるようにします。最初は接続・権限・実装できる範囲を調べ、Mac内の専用テスト会話から始めます。

### 自分の条件を記入する

| 項目 | 記入する内容 |
| --- | --- |
| 使う眼鏡 | 機種、OS、AIUIの利用可否 |
| Mac | OS、開発環境、常設稼働できる条件 |
| AI | 利用しているアプリ・CLI、アカウント、使える接続方法 |
| 資料 | 読み取りたいObsidian、Google Driveなど。秘密や本文はここへ貼らない |
| 作業 | 調査、相談、文書作成など、最初に実現したい1つの体験 |
| 確認方法 | 眼鏡、本人用Web、Macのどこで何を確認するか |

### コピーして使う依頼

```text
「私のAI V2」の参考資料を読み、自分用の似た仕組みを作るのを手伝ってください。

目的は、眼鏡から自然に話して、MacのAIとの会話と仕事を続けることです。
README、CONCEPT、ARCHITECTURE、BUILD_GUIDE、REFERENCE_SPEC、SAFETYを先に読んでください。
この公開資料には実働版のソース一式やインストーラーはありません。
掲載されたJSON例は説明用で、互換APIではありません。

最初に、私の環境と、現時点で利用できる公式の接続方法を確認してください。
使える接続と未確認の接続を分け、実現可能な構成と、足りない部品を説明してください。
特に、独立したCodex会話への接続と、開いているデスクトップ会話への接続を混同しないでください。

利用者は、質問・依頼・説明を分類せず自然に話します。
固定キーワードで意味理解を狭めず、情報が足りない場合は自然に聞き返してください。
会話先を判断する受付AIには、ファイル操作やスキル実行の権限を与えません。
実作業は、選ばれたMac会話が担当します。

まず専用のテスト会話へ文字を1回送り、完了状態と本文を読める最小構成を作ってください。
それから依頼状態の保持、認証付き眼鏡表示、実音声、会話先確認、既存会話への接続、
進捗・結果・聞き返しの共有、確認後の変更、復旧・終了へ段階的に進めてください。

実会話ID、対象、表示した質問、元の依頼、送信状態はMac側で照合します。
通信の結果が不明な依頼を自動再送しないでください。
古い質問への返答や、文脈に合わない音声認識を、同意として使わないでください。
原音と一時音声を処理後に削除し、生成Agentへ有効な秘密を埋め込まないでください。

保存・編集・送信・公開などの実行直前には、対象・内容・影響を示し確認を受けてください。
使用する道具やスキルの権限とルールは維持してください。
新規契約、課金、外部公開、本番設定の変更を、最小構成の準備に混ぜないでください。

端末操作を頼む前にMacで準備できることを済ませ、目的・操作・所要時間を説明してください。
模擬確認、Mac確認、実機の音声・表示確認を分けて報告し、合格済みの操作を繰り返さないでください。
自分の環境で確認していないものを、再現済みや完成と報告しないでください。
```

この依頼文は、認証、権限、実機検証の代わりにはなりません。AIの提案したAPIや権限が実在するかを公式資料と自分の環境で確認し、必要な部品を作ります。

## 認証 録音 実行確認の設計

自然に話せることと、どこへ何を実行するかを正確に扱うことを両立させます。受付AIの自由な説明だけで権限を決めず、Mac側が実対象と確認状態を照合します。

### 端末の登録と接続

初回だけ本人が眼鏡を確認して登録し、その後は登録済み端末がその回の接続を取得する構成です。端末登録と短命な会話接続を分け、Macで期限と失効を管理します。

生成Agent、Git、URL、ログへ有効な秘密を埋め込みません。「非公開Agent」と表示されていても、生成ファイルの取得まで認証で守られるとは想定しません。トンネル管理用の秘密もMac側だけで扱います。

AIUIにはAgentごとの保存機能がありますが、専用の安全な鍵保管庫であるとは扱いません。保存失敗、破損、登録解除、紛失、再起動、資源更新でどうなるかを自分の実装と端末で確認します。[AIUI保存APIの公式資料](https://github.com/yodaos-project/AIUI/blob/main/documentation/3-api/storage-api.en-US.md)

### 録音は利用者の1回操作で始める

起動だけでは録音しません。「タップして話す」または「タップして続けて話す」の1回操作を録音開始の意思確認にします。録音中であることを表示し、話し終えたときの手動終了と最長60秒を設けます。

毎回の二段階確認は入れません。原音と一時音声は処理後に削除し、失敗、取消、終了の経路でも削除を確認します。文字化した発言や会話履歴は別に残るので、音声削除がすべての記録削除を意味するわけではありません。

Whisperへ渡す前にVADで発話区間を確認します。無音からの誤った文章生成を減らしますが、周囲の実在する声やテレビ音声を完全に分離するものではありません。

### 意味理解と確定を分ける

受付AIは元の発言、会話の文脈、候補を読みます。候補の名前や内容を参照データとして扱い、そこに含まれる指示で受付の権限を変えません。

会話先の提案はMacの実会話へ解決します。AIが作った呼び名だけを画面に出して送信しません。確認中の返事が文脈に合わない場合は、元の依頼と対象を保持して聞き直します。

### 読んだ質問と返答を結ぶ

眼鏡へ表示した回答の識別情報と、Macの最新質問を照合します。WebやMacで会話が進んだ後の古い「はい」を、新しい変更の承認に使いません。質問が違う、または照合できない場合は送信を止めて最新内容を示します。

### 実際の変更直前に確認する

保存、編集、送信、公開、削除、予定登録、購入などは、対象・内容・影響・権限を一致させて確認します。これは設計上の共通境界であり、列挙した全操作がV2で実機検証済みという意味ではありません。

確認後に対象や本文が変わった場合は再確認します。録音開始や会話先への同意を、別の文書変更への同意に流用しません。利用するスキルが公開を禁止している場合なども、そのルールを維持します。

### 応答が不明なら状態を読む

依頼ID、送信意図、実会話先、元の発言を保持します。通信が切れても、送ったか不明という理由で同じ依頼を無条件に送信しません。同じ依頼の状態と結果を読んで照合します。

失敗報告だけでは、途中の変更がなかったとは限りません。実際の保存先やサービスも読み戻します。眼鏡の終了を、Macで始まった仕事の取消や実行済み変更の巻き戻しとして扱いません。

これらは検証した条件での設計と対策です。あらゆる競合、故障、サービスの組合せで完全な一回実行を保証するものではありません。[検証範囲](#実機で確認した範囲と制約)

## 実機で確認した範囲と制約

以下は、2026年9月26日までに確認した、作者の個人用V2の記録を要約したものです。対象はRokid AI Glasses RV101と作者のMac環境、Agent版0.36.13までです。公開資料の初版は2026年10月10日です。

このリポジトリは資料公開です。ここに実働版のアプリは含まれず、別の人の環境での再現成功を確認したものでもありません。私用版の合格と公開資料の検査を区別します。

### 確認した体験

| 項目 | 確認した範囲 |
| --- | --- |
| 既存会話の継続 | 自然な発話から実在するMac会話を選び、返事をRV101で確認 |
| 新しい会話 | 送信先の提案を確認し、新規Mac会話の最初の返事をRV101で確認 |
| 実会話名の表示 | Macが選んだ送信先名を眼鏡で確認 |
| 途中経過と最終回答 | 自動更新、同じ本文の再描画抑止、最終回答への自動切替 |
| モデル表示と切替 | Mac会話の実モデルを版付きで表示。使用中モデルと明示した標準を分離 |
| Obsidianの読み書き | 読み取り、確認後の新規文書、追記、既存文書の編集。本文と一件性を読み戻し |
| Google Driveの利用 | 接続・検索、確認後のDocs作成・追記、Sheetsの特定セル更新。実結果を読み戻し |
| スキルの実行 | 音声依頼からWeb調査、Obsidian新規文書、Googleスライド作成を一巡 |
| Macからの追加入力 | Rokid起点の処理中の追加コメントが同じ作業へ反映され、最終回答が戻る |
| 古い質問への返答 | WebやMacで会話が進んだ後の音声を送信せず、最新回答を表示 |
| 最新質問への返答 | 眼鏡に表示した質問への音声返答を、同じMac会話へ1回送信 |
| 新しい質問の自動表示 | 眼鏡を開いたまま、Mac側の新質問が会話へ追加表示されたことを本人が確認 |
| 通信切断からの回復 | 実音声受付後に通信を1回切断。同じ依頼を二重送信せず回復し、返事を本人が確認 |
| 再起動後の復旧 | Macの常設受付の自動起動と保存状態、Mac・RV101再起動後の会話復旧 |
| 終了後 | 原音・一時音声が残らず、短命な接続が終了したことを確認 |

新質問の自動表示は、閉じた眼鏡への自動通知の確認ではありません。通信回復の合格は、すべての切断タイミングやネットワーク条件を網羅するものではありません。モデルやサービスの利用範囲も、この個人環境の条件によります。

### 合格とする証拠

実声、本人の画面確認、Macの送信記録、成果物の独立した読戻し、後片付けを組み合わせています。模擬テストやMacだけの合格を、眼鏡の実音声・実表示の合格に置き換えていません。

実験用の音声、私的会話、文書本文、端末ID、接続先、認証情報を含むため、生の検証ログは公開していません。上表は作者の検証記録の要約であり、第三者による認証や保証ではありません。

### 使う上での制約

- Macがログインして必要な受付と通信が動いていることが前提です。
- 眼鏡の小さな画面では長い本文や複雑な確認が読みにくいため、本人用WebやMacも使います。
- 音声認識は聞き違い、無音、周囲の声を考慮する必要があります。
- Codexの接続、モデル、道具・スキル、Google Driveなどは、利用者のアカウントと権限に依存します。
- 既存デスクトップ会話への接続部には、アプリやバージョンへの依存があります。

### 確認していないこと

- 他の利用者による通し再現、別アカウントでの同じ接続。
- RV203などRV101以外の機種、Windows・Linux・別のMac構成での同等動作。
- すべてのスキル、送信・公開・共有・削除・購入・予定登録など、全種類の実変更。
- 閉じた眼鏡への通知、Pixel Watchの通知・操作。
- すべての通信断、休止、再起動、同時更新の組合せ。
- 端末の秘密保管の耐タンパー性、長期の互換性、電池への影響。

構想段階にあった通知や記憶機能を、今回のV2完成範囲に含めて紹介していません。
