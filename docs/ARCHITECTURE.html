システム構成

V2の中心は、眼鏡とMacの通常の会話をつなぐことです。認証、文字起こし、会話先の判断、送信、結果の表示を分け、実作業はMac会話が担当します。

部品ごとの役割

部品 担当 担当しないこと
RV101のAIUI Agent 録音開始・終了、音声送信、状態・会話名・返事の表示 ファイル編集や資料作成の実処理
通信経路 固定HTTPS名からMacの必要な受付へ届ける AIの判断や、アプリ利用者の本人確認の代替
Mac受付サービス 登録端末の照合、短命な接続、依頼と表示状態の保持 眼鏡から指定された任意の会話IDを無条件に採用すること
WhisperとVAD Mac内で発話区間を確認し、音声を文字へ変換 会話先の判断、背景話者の完全な分離
受付AI 元の発言と文脈から会話先を提案、必要なら聞き返す ファイル操作、スキル実行、権限付与
会話への接続部 実会話先を照合し、元の発言を送り、進捗と結果を読む AIの言い換えから勝手に別の依頼を作ること

依頼から結果まで

  1. 利用者の操作で録音し、認証済みの接続から音声をMacへ届ける。
  2. Macが文字化し、原音と一時音声を削除する。
  3. 受付AIが現在・別・新規の会話を判断する。
  4. 別会話・新規会話では、Macが実際に解決した会話名を表示して確認する。
  5. 会話と依頼を固定し、元の発言を1回だけ送る。
  6. Mac会話の途中経過と最終回答を、同じ依頼に結び付けて読む。
  7. 変化した本文だけを眼鏡へ表示する。聞き返しへの返答も同じMac会話へ戻す。

端末登録とその回の接続

初回の本人確認付き登録と、その後の会話接続を分けています。生成したAgentに有効な秘密を埋め込まず、登録後の実行時に端末へ渡す設計です。

登録済み端末でも、会話に使う接続は短命にします。Macが期限と登録解除を管理します。端末保存のAPIがあることと、秘密を安全に保管できることは同義ではありません。安全の設計

通信経路

個人環境では、専用の固定HTTPS名とCloudflare Tunnelを使っています。Macから外向きにトンネルを張り、ローカルの受付へ届けます。これはCloudflareの公式の接続モデルに基づく構成です。

トンネルだけで、利用者の認証や操作権限が決まるわけではありません。眼鏡の登録、短命な接続、本人用Webの認証、公開する経路の限定を別に設計します。常設Macの待受けと、会話ごとの接続を区別します。

Codex接続の重要な違い

Codex App Serverには、会話を作成・再開し、入力を送り、イベントを読むための公式資料があります。OpenAI公式資料

個人環境のV2では、新規会話の初回と、既存デスクトップ会話の続きで接続方法を分けています。初回は会話を作成したApp Server接続で始め、既存会話にはデスクトップ側のキュー経路を使います。

確認した公式ページには、この既存会話用キューの同じ呼び出し仕様は掲載されていません。一般のApp Serverクライアントを作るだけで、開いているデスクトップ会話へ同じように投入できるとは案内していません。ここは利用中のアプリとバージョンで調査する接続部です。会話履歴ファイルへの直接追記で代用しないでください。

独立したテスト会話を使う最小構成と、デスクトップ会話を持ち出す完成像を、再現の手引きで分けています。

保存する状態

状態 用途 保存上の扱い
端末登録 接続を許可する端末の管理 秘密を公開物に入れず、解除できるようにする
会話先の対応 Macの会話と眼鏡の表示を結ぶ 会話IDは内部で保持し、画面には実会話名を出す
確認待ちの提案 元の依頼と実際の送信先を保持 誤認識や聞き直しで勝手に失わない
依頼の送信意図と結果 再起動や通信断での再送を避ける 依頼ID・本文・実会話先を対応させる
表示した回答の識別情報 古い質問への返答を防ぐ 回答ID、ターン、本文の識別を次の返答へ結ぶ
原音と変換用音声 文字起こし 処理後に削除し、通常の会話履歴とは分ける
